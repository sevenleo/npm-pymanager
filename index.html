Why it helps

What it does

Built for daily npm use: see everything once, decide in one keypress, trust what it reports.

Local + global, merged

One table, scope tags [L] / [G]. Installed, latest and disk size per row — [ok] or [update].

Safe by default

Only outdated packages are touched. Update-all asks (y/N) first. Failures are listed by name, table refreshes after.

Fast to operate

a all outdated, o or a number for one, r refresh, q quit. Single keypress, no Enter for menu.

Readable anywhere

Full table at ≥80 cols, compact at 60–79, cards below 60. NO_COLOR=1 and ASCII fallback included.

Install in two minutes

No registry, no build step. If you can see this page, you already have the app: the folder around it holds main.py + locales/. Keep them together.

1

Python 3.8+ and npm reachable. Run each line (Windows: python or py):

node -v npm -v python --version

Confirm the app files are beside this page: main.py + locales/en.json.

Keep one copy

  main.py
  locales/en.json, pt.json, es.json
  docs/README.md, CHANGELOG.md
  index.html (this page)

Do not separate main.py from locales/ — strings load relative to the script file. One copy serves all your projects.

3

Run at your project

Simplest: open the project folder in a terminal and run:

python main.py

Your current folder decides locals; globals always show. Same command as the hero — no second form to memorize. One copy serves all projects: cd my-app && python ../npm-pymanager/main.py. Language asks every run on purpose — no config file to maintain, one keypress (1 / 2 / 3, Enter alone is English, ~1s). This page is EN; the app UI is EN/PT/ES.

Heads up: outside a Node project the local section is usually empty — globals still show if npm resolves its global root. If you installed packages externally, press r to refetch. Sizes are measured from disk once per scope + version, then cached for the session.

Trust

What it runs, exactly

Thin wrapper over npm — same rules as npm update, so it respects your semver ranges. It never edits ranges or forces @latest. The table itself is the dry-run: review LOCAL_NEW / GLOBAL_NEW before pressing a.

  • Read: npm list --depth=0 --json + npm outdated --depth=0 --json, local and global, in parallel
  • Write: npm update only for rows flagged outdated; success only on exit code 0
  • Confirm: update-all needs y; already-current picks just say so
  • Fail soft: every npm call has a timeout; bad JSON or timeout keeps last data with a warning
  • Offline: latest columns stay empty instead of crashing

What changes on disk

Same as running npm update yourself: node_modules + package-lock.json move forward within your ranges. package.json ranges are left alone. Routine git habit: review with git diff package-lock.json, undo with git checkout -- package-lock.json + npm ci.

git status --short && git diff --stat

FAQ

Details, tucked away

Will it break my project with a major bump?

No — it delegates to npm update, which follows your package.json ranges. It never edits ranges or forces @latest. What moves is node_modules + package-lock.json. Commit before you run, review with git diff package-lock.json, undo with git checkout -- package-lock.json + npm ci. Update-all asks (y/N) defaulting to N.

What exactly gets updated?

Only packages flagged outdated. One queue, locals first then globals, tagged [L] / [G]. Already-current picks report “already updated”. Anything but y aborts update-all. After the run the table refetches once.

Workspaces? pnpm / yarn? Global permissions?

Plain npm projects only — node_modules + global root. No special workspaces / pnpm / yarn handling. Monorepo tip: run once per workspace root (locals come from your current folder). For majors or interactive range edits, pair with npx npm-check-updates. For globals, pre-check with npm root -g: if that folder needs admin rights, run the terminal accordingly or fix your npm prefix. Failures surface as [x] name, never silently.

Offline or slow registry?

Offline, the “latest” columns stay empty instead of crashing. Every npm call has a timeout and fails soft — you keep your last known data with a warning.

Small terminal? No colors?

Full table at ≥80 columns, compact versions at 60–79 (1.2.3 -> 1.3.0), vertical cards below 60. NO_COLOR=1, --no-color, TERM=dumb or piped output disables colors. NPM_PM_ASCII=1 forces ASCII.

How are sizes and languages handled?

Sizes are measured from disk (node_modules/<pkg> local, npm root -g global) and cached per scope + version — first load on huge trees takes a moment, refresh never remeasures unchanged versions. UI strings come from locales/en,pt,es.json (56 keys, keep in sync).

Can I peek without touching npm?

Yes, optionally: python main.py --test opens the same UI with example data so you can exercise the keys. It is not the main flow — daily use is python main.py.
